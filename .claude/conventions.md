# Project conventions (AI-DLC)

This is the shared source of truth the pipeline agents consult so that work
stays consistent across developers and across runs.

## Languages & frameworks

- **Frontend**: TypeScript 5 (strict) / React 19 / Vite 7 (NOT 8) / Tailwind CSS v4
- **Backend** (added Phase D): Express + better-sqlite3, TypeScript executed via `tsx`,
  SQLite database at `./data/app.db`, server listens on port 3001, Vite dev server
  proxies `/api` requests to it via `vite.config.ts`.
- Node version: 22.x. Package manager: npm.

## Test framework

Vitest 4 + jsdom + Testing Library (`@testing-library/react`, `@testing-library/jest-dom`).

- Tests are colocated as `*.test.ts` / `*.test.tsx` next to the source file under test.
- Vitest globals (`describe`, `it`, `expect`, etc.) are enabled — no import needed.
- Run tests with: `npm run test:run`

## Lint / format / type-check commands

```
lint:      npm run lint
typecheck: npm run typecheck
test:      npm run test:run
```

There is no separate format step (no Prettier configured). ESLint is the only
static-analysis tool; fix issues it flags before committing.

## Code style & patterns

- **`src/game/`** (added Phase B) MUST stay pure: no React imports, no network
  imports. It may only import from other files within `src/game/` and from
  the TypeScript standard library.
- **Tailwind v4 setup** — no `tailwind.config.js`, no `postcss.config.js`, no
  `@tailwind base/components/utilities` directives, no `content` globs.
  `src/index.css` starts with `@import "tailwindcss";` and the
  `@tailwindcss/vite` plugin is used in `vite.config.ts`.
- **UI components** depend on a `GameRepository` interface (added Phase D),
  NOT on `fetch` directly.
- **Server code** lives only under `server/` (added Phase D). Do not import
  server modules from `src/`.
- TypeScript is strict: `strict: true`, `noUnusedLocals: true`,
  `noUnusedParameters: true`. All parameters and imports must be used.
- Use `moduleResolution: "bundler"` and `jsx: "react-jsx"` (no React import
  needed in JSX files).

## Out of scope / do not touch

- `dist/` — build output, never commit or edit manually.
- `data/` and `*.db` — SQLite runtime data, never commit.
- `node_modules/` — generated by npm, never edit or commit.
- Do NOT create `tailwind.config.js`, `tailwind.config.ts`,
  `postcss.config.js`, or `postcss.config.cjs` — Tailwind v4 forbids them
  when using the Vite plugin.

## Security rules

- No secrets committed to the repo (no API keys, passwords, tokens in any file).
- The Express API is local-only (localhost:3001); it is not exposed publicly.
- A client-asserted `player_id` is UX scoping, NOT a security boundary.
  Reviewers MUST NOT flag this as a bug. Do NOT add authentication.
- Do not add dependencies with known critical vulnerabilities without explicit
  approval.
